# AFOS local draft recovery

English | [中文](ENTERPRISE_RECOVERY.zh.md)

Status: implemented source and Linux filesystem/fixture tests. This module is not an activated Desktop login, Host, UI or background uploader. Its transport must be owned by trusted Main and connected to the fixed Enterprise Broker actions. Windows/macOS installation, real IdP, Session recovery and server storage restore remain unverified.

`EnterpriseRecoveryStore.open(base, binding, transport)` creates `base/afos-accounts/<sha256(issuer, subject, organizationId, deviceId)>/{profile,home,cache,outbox}`. The caller supplies an already authenticated binding and one exclusive Main owner. Personal files stay in their existing location. `close()` aborts old requests and closes the handle before the caller switches the Host/account. Another account gets a different directory and never receives the old transport. The caller must stop the old Host, close its connections and prevent Renderer/Agent access to the store, input snapshots and transport object.

Only versioned, bounded draft records are persisted: the actual hashed input snapshots, immutable Run/release/policy/source references, official Session reference, local editable draft, fixed archive idempotency key, coarse execution projection and recorded server receipt. No credential, model prompt, tool trace, arbitrary path, endpoint or script field belongs to this contract. At most eight drafts and eight MiB of encoded metadata/text are kept. Exceeding a limit refuses the write and retains existing records; there is no automatic deletion or retention of user files. Draft text and input snapshots are explicitly local enterprise plaintext, protected by file access rules rather than an assertion that downloaded content can be remotely erased.

`createDraft()` requires current server authority and an unchanged server-validated Run. `editDraft()` can edit an existing local copy offline until an archive intent or receipt exists. `archive()` is explicit and starts with current authority, receipt lookup and current authority again. A recorded server receipt is checked against Run/attempt/content hash. When the server reports no archive, the module validates current Run/ACL/release/policy/input/device/expiry again. Before the first possible upload it atomically publishes and fsyncs `needs-reconciliation`. Any unknown response, malformed receipt, process exit or retry remains query-first. A prior receipt can be reconciled after Run expiry, but expiry never allows a new upload. Root integration must provide `assertCurrent`, `validateRun`, `getReceipt` and `archiveDraft`; the persisted Run itself is not an authorized handle.

Concurrent archives are refused, and there is only one draft per Run/attempt. Pending and archived contents cannot be changed under an existing key. A safe rerun requires a newly authorized Run/attempt, the same project/release/source pins and an explicit predecessor reference. Opening stored data never creates work, calls the server or resumes a Session. Previously queued/running/cancel-requested records become `interrupted`. There is no claim of recovering an uncommitted model stream or of continuing work after the process exits.

The trusted official Session subscription may project the public DSH 0.1.7-rc.2 `turn/start` and `turn/end` envelope (`type`, `seq`, `time`, `data.turn`, `data.reason.kind`) through `projectSessionEvent()`. The envelope and completion reasons were checked in the pinned DSH public Session source. Sequence deduplication also binds namespace/Run/attempt/Session, so old attempts cannot overwrite newer projections. Projection retains no message/error body and never changes archive state or starts an Agent. `aborted` is interruption evidence; `cancelled` is recorded only through the trusted caller after actual Host/process stop confirmation and is terminal for that Run/attempt. Archive responses merge only archive fields into the latest projection; pending network responses cannot roll back newer sequence or cancellation state. Cancellation before dispatch refuses a new upload; a server commit that already happened can still be recorded alongside confirmed local cancellation. A disk receipt is cached server-response evidence with `lastSyncAt`; it is not fresh authorization, a server witness of local execution, or a substitute for receipt lookup when online.

POSIX uses private directory/file modes, current uid checks, ancestor/regular-file/link checks, `O_DIRECTORY`/`O_NOFOLLOW`, descriptor/path identity checks, an exclusive random temporary file, fsync, atomic rename and directory fsync. Every managed directory and its parent are synchronized before use, including previously created directories left after failed startup. A failure after rename closes the store so stale memory cannot overwrite a newer disk generation; reopening validates the disk record. The caller must provide a canonical absolute existing base path. The module refuses links/hardlinks, permissive managed paths, corrupt data and unknown contract versions without resetting or overwriting them. Node path operations still have a same-user directory/reparse-point race; this is not a native hostile-filesystem boundary or an Agent sandbox. Desktop single-instance ownership is required; the in-process ownership check is not an OS lock.

Windows defaults to `recovery/platform-acl-unverified` and needs an independently verified `verifyWindowsAcl(paths)` native adapter for managed directories and files. POSIX modes, Linux tests and an injected callback cannot satisfy Windows ACL or macOS installation acceptance. Real protected Profile/Home wiring, power/suspend events, actual Host exit, official Session checkpoint/old-version compatibility, encrypted credential restore, server database/object storage recovery and target-platform signing still need their own evidence.

Rollback: retain an untouched copy of the account directory and test it with the previous compatible reader in an isolated profile. Do not replace personal Home, edit official Session logs, copy Token files into this store, or infer a database rollback from application rollback. Unknown store versions fail closed. Server files/metadata/receipts, official Sessions, desktop draft records and OS-protected credentials have separate ownership and must be restored separately. Removing these source files does not reverse a completed archive. The fixture backup test verifies only this v1 local draft reader; AT-50/51 remain NOT_RUN.

Evidence mapping: D09 AT-40/41/42/43 and the account-binding portion of D05 AT-13/14 receive focused fixture/filesystem coverage; D09 AT-31 is not established by this module. D11 AT-48/49 remain blocked by target machines and verified OS adapters. D12 AT-50/51/52 require real upgrade/restore and whole-product independent review. Fixture pass is not formal acceptance pass.

Root integration now composes this store with private Main OAuth/Broker, current authority, encrypted credential rotation/restore and query-first archive. Logout cleanup drains outstanding credential writes; a failed old deletion must complete before that namespace may publish a new credential. Ordinary caller cancellation and account lifetime abort pending model reads without relying on a cooperating stream body. Main rejects expired authority before Host startup. Native Electron account/project/sign-out menus are included in the carrier only when a distribution-owned `afos-desktop-config.json` is present inside the application. No environment or Renderer configuration is accepted. Its exact fields are `contractVersion: afos.desktop-config.v1`, `releaseId`, `policyRevision` and `auth: {issuer, clientId, resource, scope}`; issuer is HTTPS, resource is exactly issuer path plus `/afos`, and scope is `afos` optionally followed by `offline_access`. Do not place credentials in this file.

The optional carrier entry invokes no login at startup and receives no credentials from Renderer/Agent. Its script-free status window offers native trusted user account actions. Without this file the existing personal carrier starts normally. The enterprise entry does not start the personal Profile: its Host capability remains `ingressValidated: false` and `sandbox: unavailable`, so enterprise Host startup fails closed until actual Profile ingress and native isolation are verified. Full Loader/Agent/Session/LLM/Client assembly, raw HTTP/WS closure, draft UI and target-platform validation remain unfinished. Neither source integration nor native menu compilation establishes G3.
