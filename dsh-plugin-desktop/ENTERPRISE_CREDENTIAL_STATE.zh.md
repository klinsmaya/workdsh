# 企业登录凭据存储状态

D04 与 AT-11 要求在操作系统加密不可用（含 Linux `basic_text`）时明确显示仅内存登录状态。Main 独占凭据，在核对账号 generation 后才记录当前 refresh token 的持久化结果。登录与项目切换会清除旧持久化状态；迟到的旧写入不能更新新账号。

原生账号菜单显示三个有限状态之一：未登录、登录凭据仅保留在本次会话内存中、refresh 凭据已加密保存。账号操作成功时，内存模式还明确提示重启 WorkDSH 后需重新登录。展示信息不包含 token、账号标识、namespace、文件路径或加密后端细节；不增加 Renderer 或 Agent 的凭据 IPC。

Main 在私有边界观察认证变化与持久化结果，因此后台刷新或撤权也会更新原生菜单。token 轮换时先清除旧的已保存状态，再公布新的持久化结果。原生观察回调抛错不会改变认证或业务权限；应用退出时解除菜单订阅。

受控 Main 测试覆盖拒绝持久化且不产生 Vault 文件、refresh 轮换后转为内存模式、迟到的旧账号写入。它们不代表真实 IdP 或 Windows/macOS 验收。最终载体 AT-11 还需消费真实 Electron unavailable/basic_text 证据并检查测试自有磁盘。原始验收要求满足前，P1 G3 仍未通过。

回滚时一并还原本切片的 Main 状态与原生菜单展示，保留已有加密 Vault 与本地草稿。本变更不含数据迁移、依赖更新、权限扩展或 Host 激活。
