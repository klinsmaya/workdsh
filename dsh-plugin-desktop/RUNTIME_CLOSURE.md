# ADR: one fixed runtime graph for personal and enterprise consumers

This local Linux component packages the existing public CLI, app/Loader and Web/Slots dependencies with the WorkDSH personal and enterprise packages. It creates one physical dependency graph and one Node executable. The original personal composition remains selectable from that graph; the existing Main-owned enterprise CLI still creates its empty managed Profile and fixed private patch. No second Host, Loader, transport, Agent loop or approval engine is introduced.

Source20 is `a7b9d9760d7b3908c8ccf84779a2fc6a8178e41b`, upstream `477b4f420553e8a52c2fbccc464d7561b239c443`, DSH `0.1.7-rc.2`, Cordis `4.0.4`. The upstream primary-runtime lock already declares Node `24.21.0` and the Linux x64 archive checksum. Earlier AFOS checks ran Node `24.19.0`; this new packaged interpreter needs separate compatibility and relocation evidence. Preparing this component does not change the DSH/NocoBase/peer pins or claim those older checks used the new interpreter.

Initial real materialization/consumer evidence uses the preserved Source20 artifacts. The final resolver manifest samples clean Source21 `5886f8ec0ad732d27c19b851009f1ed7794ca4ad`, whose reviewed compiled provider adds the public stateless `local-drafts` view. It is rebuilt from that source, not relabeled. Source21 remains separate from subsequent optional Electron/UI/CallerProof integration.

Build inputs are an explicitly trusted, frozen source/dependency installation and the hash-verified official Node archive. Only package shipping files, resources and the production dependency/required-peer graph are materialized. WorkDSH `workspace:` and model-adapter `file:` references become exact packaged versions. Internal package links remain contained in the output. User Profiles, patches, credentials, environments, agent homes, source caches and package-manager configuration are not build inputs.

The standalone model-adapter development install has duplicate same-version Cordis/DSH services. The artifact chooses the original CLI/Web graph's first exact-version official DSH-family providers and one Web-anchor Cordis `4.0.4`; it records every discarded source-context alias. This packaging projection changes no official code or pin. All dependency and peer declarations, including overlapping declarations, must satisfy the selected exact provider or an explicit existing `workdsh-web/package.json` pnpm override. Published npm aliases retain their original import name and alias meaning.

The shared public `node-addon-native-custom-loader` dynamically resolves the target optional package from its own module context. A metadata-only graph with just the personal/enterprise roots lost the original pnpm hoisted lookup. The finite root `node-addon-require-builtin-linux-x64-gnu@0.1.6` restores this already installed target provider; the native loader and binary remain unmodified. The failed first artifact and actual native attempts are retained. Actual NAPI loading and original CLI startup must follow byte-only verification.

Declared dependencies alone are insufficient for the existing first-party packages: bundle client code imports Workbench and LLM while its manifest labels them development dependencies. The fixed graph therefore supplements only actual literal references from the curated shipping JS/MJS/CJS, resolved through the existing installed public providers, and normalizes those edges into exact artifact runtime dependencies. It does not copy the general development graph. An output scanner then resolves every identified literal reference and rejects missing/escaping targets. TypeScript `6.0.3` public `createSourceFile`/`forEachChild` AST owns parsing; nonliteral expressions remain outside static coverage and require the existing fixed Loader composition plus real consumer tests. Earlier successful config dumps are not claimed as complete runtime import coverage.

The public resolver manifest owns fixed versions and package entry/resource requirements. The builder reads public package manifests and Node resolution paths; it does not copy upstream implementation into owned source or execute package install hooks. Runtime verification rejects missing or changed files, escaping links, mismatched versions, multiple physical DSH installations and missing declared dependencies/peers. The artifact is a Linux development component, not a signed Desktop release.

Reuse record: D01/D02/D07/D12; existing `EnterpriseCliHost`, public `@deepseek-ai/dsh/lib/bin.js`, `workdsh-provider-enterprise-profile/cli-profile`, `main-ipc`, original appReady/Loader/Core and the official Web/Slots graph. Existing Desktop preparation packages only the personal release; its primary-runtime wrapper excludes Linux. The Source20 owner tests use a workspace resolver. This component addresses packaging and consumption, not new business or execution machinery.

Main remains the business/credential authority. Packaging cannot supply Browser caller proof or native confinement. `EnterpriseCliHost.capabilities()` stays `ingressValidated:false/sandbox:unavailable`; its production start remains refused. Source21's reviewed Main-owned local-draft view is included. Its complete offline GUI routing and Main's unexpected-stop callback remain separate carrier integration work. No certificate or fixture flag upgrades these capabilities.

Acceptance support is limited to original AT-03/05/06/12/27/29/31/32/50/52 components. AT-48/49 require actual Windows/macOS installation; full native enforcement, CallerProof, real IdP/model, signing and complete offline GUI remain open. The formal matrix and P1/G3 gates are unchanged. Rollback withdraws this optional local runtime packaging delta and retains all user data, source history, Profiles, credentials, Recovery and old evidence. No publish, push, merge, deployment or database migration is authorized.

The full Linux runtime is approximately 1.3 GiB before compression and remains a separate local artifact. It is not inside the Library delivery ZIP. Every input/output byte is covered by bounded `audit/source-NNN.json` and `audit/payload-NNN.json` chunks; `runtime-integrity.json` anchors each payload chunk, and payload entries include the complete source-audit chunk set. The trusted integrity SHA must be supplied by the Main/build owner, never learned from an untrusted runtime itself.

The preProcessFile diagnostic (22 samples, exit 0) revealed that concatenated imports can be reported as literal prefixes and require.resolve is omitted. The packaging implementation therefore uses the same locked TypeScript 6.0.3 public AST API. Literal import/export/require/import()/require.resolve references are exact; concatenated and variable expressions are explicitly recorded. Scope/binding analysis is not a JavaScript theorem: a shadowed require may be conservatively over-included. This artifact does not assert arbitrary executable configuration closure.

The manifest contains an exact dynamic-reference support table. Profile fixed-name require.resolve rows retain the original public composition and are exercised by real managed CLI/Core consumers; the native assembly variants have resolution support, with production caller-proof execution OPEN. The Office PDF fallback `import(this.workerSrc)` is an explicit OPEN browser resource path. An unrecognized dynamic row or changed occurrence count fails packaging. Zero parser errors alone does not certify a complete desktop product. Legacy personal marketplace/Skillhub addons, the Office Python runtime, target OS sandbox/signing, and future preload/renderer carrier resources remain outside this Source21 Linux fixed CLI artifact.

## Reproduce this local component

Prepare the exact clean manifest revision with its existing owning-lock dependency installation and reviewed first-party shipping dist; this command never installs dependencies or executes npm hooks. Supply the official Node archive whose SHA is fixed in the manifest:

```sh
node dsh-plugin-desktop/scripts/prepare-fixed-runtime.mjs /trusted/source dsh-plugin-desktop/enterprise-runtime-manifest.json /trusted/node-v24.21.0-linux-x64.tar.gz /new/runtime-root
node dsh-plugin-desktop/scripts/verify-fixed-runtime.mjs /new/runtime-root OWNER_SUPPLIED_INTEGRITY_SHA256
```

The builder prints the integrity anchor. Preserve it outside the runtime under the build/Main owner's control. Verification requires that external value. After relocating the complete directory, resolve the original CLI from that directory's `package.json` and launch it with its own `bin/node`. Do not substitute the toolchain's interpreter or workspace module lookup. The test runner accepts explicit `source-test-snapshot runtime anchor new-output public|owner|core|personal` arguments; the Main/IdP/consumer fixtures stay separate test inputs, never product packages. The personal case performs only the original fixed composition dump; it grants no Agent/Web startup.

A local tar.gz retains the one directory graph, relative links and complete chunk audits. Extract only an owner-verified archive into a new local directory with `--no-same-owner`, then run the verifier with the separately recorded anchor. This is a local Linux development deliverable, with no publisher certificate, updater registration or production activation. Its full binary/archive bytes stay outside the Library ZIP; the small source delta, raw receipts and complete chunk/index provenance are the reviewable handoff.
