# Explicit fresh enterprise window after Renderer crash

The native enterprise account owner keeps its existing Main session, project selection and local Recovery store. A real `render-process-gone` event synchronously revokes the old document/caller owner and stops enterprise execution. It displays the existing local face and waits for another explicit native Start action. Ordinary document reload keeps its existing lifecycle and does not start a Host automatically.

Native Start precreates a BrowserWindow through the same local-window factory, with the original sandbox/context-isolation preferences and a new nonpersistent partition. The old physical window remains alive while the old local IPC registrations/account watcher and online request hooks are disposed. The new factory then installs its own handlers and loads the existing local renderer. Only after this owned window is ready may the existing CLI/Core start and perform the original private index/cookie exchange. The old physical window closes after replacement readiness, so replacement does not produce an intermediate `window-all-closed` event.

Native Close synchronously revokes the document/caller, prevents immediate destruction and waits for existing Host cleanup before destroying the last window. Repeated Close requests share that drain; Start is refused while it is pending. A failed drain retains the physical local shell and refuses online Start. The native carrier's existing `before-quit` cleanup remains in place. After native Close owns the stop, `closed` does not enqueue another stop that could race the quit/suspend account cutoff.

While Close owns this window's drain, Renderer-crash and document-load cancellation callbacks share that stop. Intentional close cancellation does not report a second cleanup failure; a pending Start still returns its load failure and performs its own bounded rollback. Other owners and failures outside Close keep their normal cutoff behavior.

Old `closed`, Renderer-crash and local-load failure callbacks use owner identity guards. Repeating the old owned close callback cannot clear the new Main window reference, remove its IPC handlers or stop its Host. The strict online `mainFrame`/top-frame/URL checks and finite caller issuer are unchanged. Start concurrency and explicit stop/account/project/suspend cutoffs cannot admit a pending old Start.

Replacement construction, IPC installation or local load failure stops the Host and refuses online entry. A failed prepared window is destroyed. The old physical local shell stays available for another explicit native retry; after its owner was disposed, its old IPC capabilities remain revoked until a fresh replacement succeeds. No Run, prompt, Agent promotion, old lease or model task is replayed automatically.

Native Close during replacement preparation also cancels that Start. Rollback clears the closing marker only when it belongs to the discarded replacement, whether page readiness or Host drain completes first. A delayed Close continuation cannot destroy a later owner or clear that later owner's pending Close. The old physical shell remains available for the next explicit retry.

Author verification includes sixteen bounded lifecycle probes, the existing Desktop tests and real Main/CLI regressions, plus a real Linux Electron 43.3.0/Xvfb component fixture using the original CLI, 23-module loader and SDK. The real fixture checks Renderer crashes and explicit replacement, distinct window/Session/partition/frame/cookie/private readiness, disposal-before-install ordering, late owned callback isolation, ordinary reload, Host crash, project/account changes, retained local drafts, suspend and current-window close. Two additional real native Close cases hold the replacement readiness and real Main stop completion to exercise both completion orders, then explicitly retry and check the later owner. One explicit fixture Run prepares the baseline draft; every restart retains it without another Run or model request. The real test uses native Close and observes quitting without holding it; the owned Close path must drain first. The final Close also receives a real Renderer crash while drain is held and verifies one owned stop. It then invokes real Main suspend and verifies no duplicate Close stop or cleanup failure. It does not claim the complete production app-quit chain. It replays only the owned factory callback, never Electron's internal runtime listeners. Earlier forced destruction of the last window with an active Host intermittently stalled Electron cleanup; those failed runs remain explicit evidence, not acceptance passes.

The first failed runs and fixture corrections remain in the owner evidence. The Linux fixture uses `--no-sandbox` for the controlled runner and does not establish OS sandbox acceptance, Windows acceptance, real identity-provider credentials or production capability. Author results do not replace the independent frozen-source review. The original formal acceptance matrix remains 60 total: 2 PASS, 12 BLOCKED and 46 NOT_RUN; G3 remains NOT_PASSED.
