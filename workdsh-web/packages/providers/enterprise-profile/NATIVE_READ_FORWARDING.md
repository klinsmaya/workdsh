# Optional owned native Session reads

The existing `bootEnterpriseCore` remains the default. The named `bootEnterpriseNativeReadCore` export is an explicit headless composition for D08/D09 engineering; it does not activate or certify the desktop carrier.

The original public Loader Group contains two private scopes sharing one original Connection, with no private WebServer or listening port. One scope owns the original SessionController and its dependencies. The second owns the original Gateway and Typert definitions for five owned reads, while isolating Controller, file, LLM and preset service aliases. The parent Connection retains its original fixed Ingress and seven draft methods.

Only `session/list`, `session/page`, `session/projections`, `session/follow` and `session/control` are forwarded. The Runtime selects only the latest successfully started, still live official Agent/Session; the caller cannot select another history, actor, project or path. Every invocation asks the private Main `ownedSessionRead` capability for fresh account/project/Recovery ownership and a stable Host epoch, revocation signal and bounded expiry. This grant is separate from completed execution or an expired Run lease. A per-request immutable admission lives in standard AsyncLocalStorage through the original calls. Direct private Gateway reads without this scope refuse. Each response await and original stream frame checks the selected Session and expiry; timers and consumer exit close the business lease.

The three unary reads use the original private Connection SharedFetch handler and exported envelope schema. Follow/control use original `wireStream.open` values through Ingress `openNative`; this is an in-process carrier hook, not a new transport, mux or renderer. Stream methods are refused over unary HTTP. Returning an unstarted consumer closes our lease immediately and calls the original iterator return once. The original upstream generator's own unstarted uplink cleanup is not proven by this observation.

The private original SharedFetch handler still includes its original trusted file/upload capabilities. It is never exposed as a browser or carrier handler. The parent has no file/upload owner, and the reviewed caller guard is a separate carrier integration requirement. No raw Gateway, WebSocket mux or `$events` source is enabled by this composition.

Validation uses Cordis 4.0.4 and official DSH 0.1.7-rc.2 packages. The real-Core test in `enterprise/plugin-agent-bridge/src/server/__tests__/native-session-flow.integration.mjs` exercises actual Main/Broker/Recovery, official Loader/Agent/Session/Controller/Gateway and protocol, with a deterministic idle model fixture. It covers three reads, parallel streams, shortened real-grant expiry, late projection, direct refusal, parent raw-route refusal, Main revocation, unstarted return, and selection changing during response JSON consumption. Existing Profile 20 and default Core 18 checks remain separate regressions. These tests do not constitute formal AT acceptance.

Cold history, full native Conversation/SessionProvider mounting, original Client `$events` generation, actual Electron cross-process carrier wiring, target Windows/macOS, full sandbox/SRT, real identity provider and models remain unverified. P1/G3 and desktop activation remain refused; D13/D14 are not enabled by this module.

Rollback removes this opt-in contribution and its package references, then rebuilds the original Profile. It requires no schema migration or deletion of sessions, draft data or the optional derived index. Preserve all existing user changes.
